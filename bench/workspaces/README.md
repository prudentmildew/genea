# Reference workspaces

The workspaces the benchmark harness measures Genea on (see *Reference
workspace* in `GLOSSARY.md`, and #19, Benchmark harness). Genea budgets apply in
full to **Typical**; **Large** must stay usable.

Nothing here is committed output: both workspaces are built into `out/`
(gitignored), and both scripts take another directory as their last argument.

| Command (from `bench/workspaces`) | What it does |
| --- | --- |
| `typical/setup.sh [--typecheck] [DIR]` | Generate Typical into `DIR` (default `out/typical`), commit it as its own git repo, install `node_modules` from the frozen lockfile, report its figures. `--typecheck` also runs TS 7 (tsgo) over it. |
| `large/fetch.sh [--ignore-scripts \| --no-install] [DIR]` | Clone vscode at the pinned commit into `DIR` (default `out/large`), install it, report its figures. |
| `npm test` | Unit tests for the generator (no network). |

Requirements: Node ≥ 24 (the scripts are TypeScript run by Node's built-in
type stripping, with no dependencies of their own), pnpm on PATH (it switches
itself to the version Typical pins), git, and the network for the first install.

## Typical

A pnpm workspace generated by `typical/generate.ts`: the root package plus
`packages/{shared,ui,web,api}` — shared domain code, a React/MUI design system,
a React web app and a Hono API — in strict TypeScript that imports across
packages and from real dependencies (React, MUI, TanStack Query, zod, date-fns,
Hono, rxjs, …). Toolchain pins follow ADR 0005: `packageManager: pnpm@11.13.0`,
`devEngines.runtime` Node 24.18.0, and TypeScript 7, Oxlint and Oxfmt in the
root `devDependencies`.

**Determinism.** The generator draws everything from a seeded PRNG, never reads
the clock or the environment, and writes the same bytes wherever it writes
(`typical/test/generate.test.ts` checks this). `node_modules` comes from the
committed `typical/pnpm-lock.yaml` via `pnpm install --frozen-lockfile`, with
dependency build scripts off (`allowBuilds: false`), so its file tree is the
same on every install: two installs into the same directory give identical
trees (paths, symlink targets and file contents, apart from pnpm's own state
files). Installs into different directories differ only in the ~100
`node_modules/.bin` shims, which embed the absolute path. `setup.sh` commits the generated tree with a fixed
author and date, so the commit id fingerprints the workspace (record it with
benchmark results); it fails if the install rewrites any generated file.

**Figures** (measured by `typical/report.ts`, which fails outside ±10 %):

| Figure | Target | Actual |
| --- | ---: | ---: |
| Packages (root + `pnpm-workspace.yaml` matches, the workspace model of #19) | 5 | 5 |
| TS source files (`.ts`/`.tsx` outside `node_modules`) | 2,000 | 2,000 |
| LOC (non-blank lines in those files) | 300,000 | 300,175 |
| `node_modules` entries (files and symlinks, all `node_modules` dirs) | 150,000 | 144,584 |

The dependency list was chosen to land near the `node_modules` target with
dependencies a full-stack project of this size plausibly has. TS 7.0.2 checks
the whole workspace in about 1 s on the dev machine (`tsc -b --noEmit`).

**Changing it.** Edit `typical/lib/manifest.ts` (packages, dependency pins,
targets) or `typical/lib/sources.ts` (the code). After touching anything that
ends up in a `package.json`, run `typical/update-lockfile.sh` and commit the new
lockfile; `npm test` fails while the lockfile and the manifests disagree.

Known gaps:

- The sources are not Oxfmt-formatted, so a save with format-on-save reformats
  the file. Formatting them would need the workspace's own Oxfmt and add ~23 %
  lines.
- The root `tsconfig.json` is one program over every package rather than a
  solution file with project references, because TS 7 rejects `tsc -b
  --noEmit` across references (TS6310, "Referenced project may not disable
  emit"). Each package also has its own `tsconfig.json`, which is what the
  language server opens.

## Large

[microsoft/vscode](https://github.com/microsoft/vscode) at commit
`2a59476c9bfcb90b3ddc372c36762471b7dfad1c` (tag 1.141.0), pinned in
`large/fetch.sh`. By default the script runs `npm ci` as vscode documents it:
its install scripts install every sub-directory and build native modules, which
needs Node 24.18.0 (vscode's `.nvmrc`), npm < 13 and the Xcode command line
tools. `--ignore-scripts` instead runs `npm ci --ignore-scripts` in each
directory vscode's postinstall would, which gives the same `node_modules` trees
without native builds.

Figures after a full install (`large/report.ts`; Large has no targets):
14,439 TS files, 4.02 M LOC, 224,102 `node_modules` entries (223,434 with
`--ignore-scripts`). A full `npm ci` took about 4.5 min with a cold npm cache
and 1.5 min with a warm one on the dev machine.

TS 7 comes in under an alias: `node_modules/typescript` is TS 6.0.2
(`npm:@typescript/typescript6`), TS 7.0.2 is `node_modules/@typescript/native`,
and the tsgo binary is
`node_modules/@typescript/typescript-darwin-arm64/lib/tsc`. Genea's "has TS 7"
check and tsgo lookup must follow the alias, or Large opens with language
intelligence off.

Large is an npm project with an ESLint config, so in Genea its installs, script
runner and format/fix on save are off (foreign tools, ADR 0001). That's fine
for what Large measures: tree, finder, search, editing and memory.
